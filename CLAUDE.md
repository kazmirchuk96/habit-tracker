# CLAUDE.md

Інструкції для Claude Code при роботі з цим репозиторієм.

## Що це

**Трекер звичок** — односторінковий застосунок: список звичок, щоденні відмітки,
стріки, статистика і «барабан» (slot machine), який випадково обирає звичку на зараз.

Інтерфейс українською — усі нові тексти писати українською.

## Архітектура

**Один файл `index.html`** = HTML + CSS + vanilla JS. Більше нічого:
немає `package.json`, залежностей, збірки, лінтера, тестів, CI.

«Запустити» = відкрити файл у браузері:

```bash
open index.html
```

Увесь JS — в одній IIFE в кінці файлу. Нові функції додавати туди ж, не виносити
в окремі файли без явного рішення: однофайловість тут свідома (застосунок
вставляється як віджет у чужу сторінку).

### Ізоляція стилів

Усе всередині `<div id="habit-tracker-root">`, і **кожен** CSS-селектор
префіксований `#habit-tracker-root`. Це зроблено, щоб віджет можна було вставити
в чужу сторінку без конфліктів стилів. **Обов'язково зберігати цей префікс** у
новому CSS. Кольори — через CSS-змінні на `#habit-tracker-root`
(`--surface-0..2`, `--border`, `--text-primary..muted`); акцент `#2FBE93`.

Усі `id` елементів префіксовані `ht-`.

### Персистентність — Google Sheet як source of truth

Бекенд — Google Apps Script Web App, URL захардкоджений як `SHEET_API_URL`
на початку `<script>`:

- `GET` → `{ habits, logs, queue }`
- `POST` → **той самий об'єкт цілком**, повна перезапись, не патч

Особливості, про які треба пам'ятати:

- `localStorage` не використовується взагалі. Немає інтернету або endpoint
  недоступний → застосунок показує помилку в `ht-save-status` і лишається з
  порожнім станом. Офлайн-режиму немає.
- **Код Apps Script не в цьому репозиторії** — він живе в Google Apps Script.
  Зміна формату даних вимагає синхронної правки там; тут її не видно.
- Якщо таблиця порожня — засівається `DEFAULT_HABITS` (≈37 особистих звичок) і
  одразу персиститься.
- ⚠️ URL публічний і лежить у коді: будь-хто з ним може читати й писати таблицю.
- Конфлікти не вирішуються: last write wins. Дві відкриті вкладки перетирають
  одна одну.

### Модель даних

```js
habits:     [{ id, text, createdAt, wheel }]   // wheel: false → поза барабаном
logs:       { habitId: ['YYYY-MM-DD', ...] }   // відсортований масив дат виконання
wheelQueue: [habitId]                          // черга «обрано зараз»
```

- `id` — `uid()`, формат `h_<base36 час>_<random>`. Колір звички детерміновано
  виводиться з `id` через `colorFor()` → `PALETTE` (6 кольорів), тому зміна `id`
  змінює колір.
- Дати — **завжди локальні** через `fmtLocal()` / `todayStr()`, ніколи не
  UTC/`toISOString()`. Інакше відмітки поїдуть на день.
- `logs` росте безмежно (по даті на кожне виконання) — поки не проблема, але
  варто тримати в голові.

## Ключові патерни

### Мутація стану

Будь-яка зміна: **`mutate() → persist() → render()`**. `render()` — повний
ререндер: `renderOverview` + `renderReelIdle` + `renderQueue` + `renderBulkAdd`
+ `renderSelectBar` + `renderHabitsList`.
Обгорнутий у try/catch, який при помилці замінює корінь текстом про помилку.

Там, де `innerHTML` отримує дані користувача, обов'язковий `escapeHtml()`
(у `createElement`-гілках — `textContent`, він безпечний).

### Inline-стани замість модалок

Модальних вікон немає. Замість них — module-level прапорці, які змінюють те, що
рендерить `buildHabitRow()` і панелі над списком:

- `editingId` → рядок перетворюється в інлайн-інпут (Enter зберегти, Escape скасувати)
- `confirmDeleteId` → рядок перетворюється в підтвердження видалення
- `resetArmed` → «Скинути історію» вимагає двох кліків (вікно 4 с)
- `bulkAddOpen` → замість поля «Нова звичка» показується панель додавання списком
- `selectMode` + `selectedIds` → режим вибору кількох звичок
- `bulkDeleteArmed` → масове видалення вимагає двох кліків (вікно 4 с)

Взаємовиключні: виставляючи один, скидати інші. `setBulkAddOpen()` і
`setSelectMode()` роблять це самі — не перемикати прапорці напряму.

### Масові операції

**Додавання списком** (`parseBulkHabits` → `addHabitsBulk`): один рядок = одна
звичка. Парсер прибирає маркери списків (`-`, `*`, `•`, `–`, `1.`, `2)`),
обрізає пробіли, викидає порожні рядки і відсіває дублікати — і проти наявних
звичок, і всередині самого списку (порівняння по `text.trim().toLowerCase()`).
`updateBulkAddHint()` показує «буде додано N · M дублікатів пропущено» наживо.
Нові звички створюються з `wheel: true`, як і через звичайне поле.

**Видалення кількох** (`setSelectMode` → `toggleSelected` → `bulkDeleteSelected`):
у режимі вибору `buildHabitRow()` робить ранній return і малює спрощений рядок
(чекбокс + назва + мета), без кнопок дій; клік по рядку перемикає вибір.
Видалення чистить `habits`, `logs` вибраних, `wheelQueue` і `lastPickedId`,
потім один `persist()`.

- `selectedIds` — **суто UI-стан**, у Таблицю не пишеться. `toggleSelected` і
  `toggleSelectAll` навмисно не викликають `persist()`, щоб не спамити бекенд.
- `renderSelectBar()` відсіює з `selectedIds` звички, яких уже немає (напр.
  після «Оновити з Таблиці»).
- ⚠️ **Панель вибору має зберігати сталу висоту.** Список повністю
  перемальовується на кожен клік; якщо текст у панелі переносить рядок, усе
  нижче зсувається і наступний клік потрапляє не в ту звичку. Тому лічильник
  займає власний рядок із `white-space: nowrap`, а підписи навмисно короткі
  («Вибрано: 3», «Точно? (3)»). Не робити їх довшими без перевірки висоти.

### Барабан (`spin`)

Не canvas і не колесо — горизонтальна лінійка чипів з CSS-transition на `transform`.

- **Переможець визначається індексом, а не геометрією**: `winIdx` обирається
  рандомом наперед, останній чип лінійки — завжди він. Анімація лише показує
  результат. Не намагатися рахувати переможця з позиції/кута.
- `loops = 6` — фіксована кількість проходів по списку, тому 5 і 40 звичок
  крутяться однаково ~4.6 с (`DURATION = 4600`).
- Ширина чипа = 62% ширини вьюпорта, clamp 150–240 px, прокидається в CSS як `--chip-w`.
- `prefers-reduced-motion` повністю пропускає анімацію й одразу показує результат.
- `isSpinning` блокує повторний клік; `renderReelIdle()` робить early return під
  час обертання, щоб ререндер не зламав анімацію.
- ⚠️ `renderReelIdle()` рахує кандидатів і складає їх у **`window._htCandidates`**,
  а `spin()` читає звідти. Крихке зв'язування: `spin()` без попереднього
  `renderReelIdle()` не має даних.
- Результат іде в `wheelQueue` (чергу «обрано зараз»), а не одразу у виконані.
  `toggleDoneToday()` при позначці виконаним сам прибирає звичку з черги.

### Статистика

- `currentStreak` — рахує серію від сьогодні назад; якщо сьогодні ще не
  виконано, стартує з учора (щоб серія не «ламалась» до кінця дня).
- `last7` в overview — сума **усіх** виконань усіх звичок за 7 днів, а не
  кількість днів.
- `pluralUk()` — українські закінчення (звичка/звички/звичок). Використовувати
  для будь-яких нових числівників.

### Інше

- Сортування списку: `default` / `neglected` (найзанедбаніші) / `active` / `alpha`
  (через `localeCompare(…, 'uk')`).
- Експорт JSON і CSV через Blob + `URL.createObjectURL`.
- Шрифти — `@import` Google Fonts (Fraunces для заголовків і чисел, Inter для
  тексту). Вимагає інтернету.
- Іконки — інлайн SVG через `ICONS` + `icon(name, size)`.
- Версія в футері прописана руками (`build v4`) — оновлювати при значних змінах.

## Підтримка цього файлу

Оновлювати `CLAUDE.md` самостійно, коли змінюється щось архітектурне:
схема даних, спосіб персистентності (`SHEET_API_URL`, перехід на localStorage
чи інший бекенд), контракт з Apps Script, механізм визначення переможця в
барабані, механізм ізоляції стилів, поява збірки/залежностей/тестів,
відхід від однофайловості.

Дрібні правки стилів, текстів чи списку звичок документувати не потрібно.
