# CLAUDE.md

Інструкції для Claude Code при роботі з цим репозиторієм.

## Що це

**Трекер звичок** — односторінковий застосунок: список звичок, щоденні відмітки,
стріки, статистика і «барабан» (slot machine), який випадково обирає звичку на зараз.

Інтерфейс українською — усі нові тексти писати українською.

## Архітектура

**Один файл `index.html`** = HTML + CSS + vanilla JS. Більше нічого:
немає `package.json`, залежностей, збірки, лінтера, тестів, CI.

«Запустити» = відкрити файл у браузері:

```bash
open index.html
```

Увесь JS — в одній IIFE в кінці файлу. Нові функції додавати туди ж, не виносити
в окремі файли без явного рішення: однофайловість тут свідома (застосунок
вставляється як віджет у чужу сторінку).

### Ізоляція стилів

Усе всередині `<div id="habit-tracker-root">`, і **кожен** CSS-селектор
префіксований `#habit-tracker-root`. Це зроблено, щоб віджет можна було вставити
в чужу сторінку без конфліктів стилів. **Обов'язково зберігати цей префікс** у
новому CSS. Кольори — через CSS-змінні на `#habit-tracker-root`
(`--surface-0..2`, `--border`, `--text-primary..muted`); акцент `#2FBE93`.

Усі `id` елементів префіксовані `ht-`.

### Персистентність — Google Sheet як source of truth

Бекенд — Google Apps Script Web App, URL захардкоджений як `SHEET_API_URL`
на початку `<script>`:

- `GET` → `{ habits, logs, queue }`
- `POST` → **той самий об'єкт цілком**, повна перезапись, не патч

Особливості, про які треба пам'ятати:

- **`localStorage` — лише локальна копія для миттєвого показу**, не джерело правди
  (ключ `ht-state-v1`, `readCache`/`writeCache`). Скрипт відповідає 2–3+ с (на телефоні
  довше), і без копії при відкритті видно порожній екран. Копія пишеться після кожного
  успішного завантаження і запису. Офлайн-режиму як і раніше немає.
- **Режим «лише перегляд» (`staleMode`)** діє від запуску до першої успішної відповіді
  Таблиці: показано копію (або «Завантажуємо…»), зверху смужка `#ht-sync-banner`, усе
  крім меню не реагує на дотики (CSS `.ht-stale`), а `persist()` **відмовляється
  писати**. Це головне: інакше застарілий стан (або порожній, якщо завантаження
  впало) перезаписав би Таблицю — раніше при збої мережі перша ж дія записала б
  список із однієї звички й затерла решту. Меню лишається доступним для повтору
  («Оновити з Таблиці»); успіх знімає режим.
- Якщо є копія зі звичками, а Таблиця повернула **порожній** список — це вважається
  збоєм, а не «усе видалено»: типовий набір не засівається, нічого не перезаписується,
  показано помилку. Порожня Таблиця без копії, як і раніше, засівається `DEFAULT_HABITS`.
- Копія зберігає внутрішню модель (з `everyDays`), тож змінюючи її форму, змінити й ключ
  кешу (`ht-state-v2`), інакше старі копії покажуть дані в застарілому вигляді.
- **Код бекенду — `backend/Code.gs`.** Це копія; розгорнутий екземпляр живе в
  Google-акаунті власника (прив'язаний до таблиці «Habit Tracker Data»). Репозиторій
  і розгортання не синхронізуються самі: зміна в `Code.gs` нічого не робить, доки її
  не вставлено в редактор Apps Script і не розгорнуто.
- **Зберігаються лише колонки `HABIT_HEADER`** (`id`, `text`, `wheel`, `createdAt`,
  `everyDays`) — будь-яке інше поле звички скрипт мовчки відкидає. `POST` при цьому
  повертає 200, а UI показує «Синхронізовано ✓», тож втрата непомітна до
  перезавантаження. Нове поле звички = колонка в `HABIT_HEADER` + обробка в
  `readState()` і `writeHabits()` + оновлення розгортання (див. нижче).
- **Оновлення розгортання**: вставити код в редактор → зберегти → Deploy → Manage
  deployments → олівець біля поточного → Version: New version → Deploy. Адреса
  `/exec` лишається тією самою, тож `SHEET_API_URL` міняти не треба. «New
  deployment» дало б нову адресу — не робити цього.
- **Перевірка після змін скрипта — зворотний прохід**: GET → зберегти знімок → POST із
  новим полем → GET → порівняти → одразу POST оригіналу назад → GET і переконатись,
  що збігається. Це повний перезапис Таблиці: робити швидко, зі знімком, і ніколи не
  тримати знімок у репозиторії (там особисті дані).
- Як знайти проєкт скрипта, якщо забули акаунт: у адресі `…/exec` замінити `exec` на
  `dev` — ця версія відкривається лише в акаунті з доступом до скрипта.
- `createdAt` бекенд повертає довгим рядком (`Sat Oct 10 2026 00:00:00 GMT+0300 (…)`),
  бо Таблиця перетворює дату на Date. Клієнт приводить її до `YYYY-MM-DD` у
  `normalizeHabit()` при завантаженні; усередині працюємо тільки з цим форматом.
- Якщо таблиця порожня — засівається `DEFAULT_HABITS` (≈37 особистих звичок) і
  одразу персиститься.
- ⚠️ URL публічний і лежить у коді: будь-хто з ним може читати й писати таблицю.
- Конфлікти не вирішуються: last write wins. Дві відкриті вкладки перетирають
  одна одну.

### Модель даних

```js
habits:     [{ id, text, createdAt, wheel, everyDays? }]   // wheel: false → поза барабаном
                                                   // everyDays: «раз на N днів», ціле 1..365
logs:       { habitId: ['YYYY-MM-DD', ...] }   // відсортований масив дат виконання
wheelQueue: [habitId]                          // черга «обрано зараз»
```

- `id` — `uid()`, формат `h_<base36 час>_<random>`. Колір звички детерміновано
  виводиться з `id` через `colorFor()` → `PALETTE` (6 кольорів), тому зміна `id`
  змінює колір.
- Дати — **завжди локальні** через `fmtLocal()` / `todayStr()`, ніколи не
  UTC/`toISOString()`. Інакше відмітки поїдуть на день.
- `logs` росте безмежно (по даті на кожне виконання) — поки не проблема, але
  варто тримати в голові.

## Ключові патерни

### Мутація стану

Будь-яка зміна: **`mutate() → persist() → render()`**. `render()` — повний
ререндер: `renderOverview` + `renderReelIdle` + `renderQueue` + `renderBulkAdd`
+ `renderSelectBar` + `renderHabitsList`.
Обгорнутий у try/catch, який при помилці замінює корінь текстом про помилку.

Там, де `innerHTML` отримує дані користувача, обов'язковий `escapeHtml()`
(у `createElement`-гілках — `textContent`, він безпечний).

### Inline-стани замість модалок

Модальних вікон немає. Замість них — module-level прапорці, які змінюють те, що
рендерить `buildHabitRow()` і панелі над списком:

- `editingId` → рядок перетворюється в інлайн-інпут (Enter зберегти, Escape скасувати)
- `confirmDeleteId` → рядок перетворюється в підтвердження видалення
- `resetArmed` → «Скинути історію» вимагає двох кліків (вікно 4 с)
- `bulkAddOpen` → замість поля «Нова звичка» показується панель додавання списком
- `selectMode` + `selectedIds` → режим вибору кількох звичок
- `bulkDeleteArmed` → масове видалення вимагає двох кліків (вікно 4 с)
- `freqPickerId` + `freqCustom` → під звичкою відкрито швидкий вибір частоти

Взаємовиключні: виставляючи один, скидати інші. `setBulkAddOpen()` і
`setSelectMode()` роблять це самі — не перемикати прапорці напряму.

### Масові операції

**Додавання списком** (`parseBulkHabits` → `addHabitsBulk`): один рядок = одна
звичка. Парсер прибирає маркери списків (`-`, `*`, `•`, `–`, `1.`, `2)`),
обрізає пробіли, викидає порожні рядки і відсіває дублікати — і проти наявних
звичок, і всередині самого списку (порівняння по `text.trim().toLowerCase()`).
`updateBulkAddHint()` показує «буде додано N · M дублікатів пропущено» наживо.
Нові звички створюються з `wheel: true`, як і через звичайне поле.

**Видалення кількох** (`setSelectMode` → `toggleSelected` → `bulkDeleteSelected`):
у режимі вибору `buildHabitRow()` робить ранній return і малює спрощений рядок
(чекбокс + назва + мета), без кнопок дій; клік по рядку перемикає вибір.
Видалення чистить `habits`, `logs` вибраних, `wheelQueue` і `lastPickedId`,
потім один `persist()`.

- `selectedIds` — **суто UI-стан**, у Таблицю не пишеться. `toggleSelected` і
  `toggleSelectAll` навмисно не викликають `persist()`, щоб не спамити бекенд.
- `renderSelectBar()` відсіює з `selectedIds` звички, яких уже немає (напр.
  після «Оновити з Таблиці»).
- ⚠️ **Панель вибору має зберігати сталу висоту.** Список повністю
  перемальовується на кожен клік; якщо панель змінює висоту, усе нижче зсувається
  і наступний клік потрапляє не в ту звичку. Тому: лічильник займає власний рядок з
  `white-space: nowrap`; підписи кнопок мають **сталу ширину** (кнопка «Видалити» не
  містить числа — воно вже в лічильнику; у режимі підтвердження вона «Точно?»;
  посилання «Вибрати всі / Зняти всі» має `min-width`), інакше кількість вибраних
  змінювала б перенос рядка кнопок. Панель «Частота» стоїть **окремим блоком під
  панеллю вибору**, а не всередині неї, і її висота від вибору не залежить. Перед
  зміною підписів перевірити висоту при n=0, n=1, усі, і в режимі підтвердження.

**Частота для вибраних** (`applyFreqToSelected`, `renderBulkFreq`): кнопка «Частота»
у панелі вибору відкриває ті самі пілюлі, що й швидкий вибір у рядку (`FREQ_PRESETS`,
«інше…», «без частоти»); пілюлі, що застосовують значення, вимкнені, доки нічого не
вибрано. Застосування пише `everyDays` усім вибраним **одним** `persist()`, очищає вибір,
але лишає режим вибору й панель відкритими — щоб одразу задати іншу частоту іншій групі;
підсумок «Частоту задано: N» показується 2.5 с замість лічильника. У рядках режиму
вибору видно поточну частоту (`🔁 …`), інакше результату не було б видно.
- Панель частоти будується заново лише при зміні стану (відкрито / «інше…»), перевіряється
  по `panel.dataset.key`, а не на кожен дотик по звичці: інакше число, яке вводять у полі
  «інше…», скидалося б, щойно вибереш наступну звичку. На кожен дотик оновлюється лише
  `disabled` пілюль.

### Барабан (`spin`)

Не canvas і не колесо — горизонтальна лінійка чипів з CSS-transition на `transform`.

- **Переможець визначається індексом, а не геометрією**: `winIdx` обирається
  рандомом наперед, останній чип лінійки — завжди він. Анімація лише показує
  результат. Не намагатися рахувати переможця з позиції/кута.
- `loops = 6` — фіксована кількість проходів по списку, тому 5 і 40 звичок
  крутяться однаково ~4.6 с (`DURATION = 4600`).
- Ширина чипа = 62% ширини вьюпорта, clamp 150–240 px, прокидається в CSS як `--chip-w`.
- `prefers-reduced-motion` повністю пропускає анімацію й одразу показує результат.
- `isSpinning` блокує повторний клік; `renderReelIdle()` робить early return під
  час обертання, щоб ререндер не зламав анімацію.
- ⚠️ `renderReelIdle()` рахує кандидатів і складає їх у **`window._htCandidates`**,
  а `spin()` читає звідти. Крихке зв'язування: `spin()` без попереднього
  `renderReelIdle()` не має даних.
- Результат іде в `wheelQueue` (чергу «обрано зараз»), а не одразу у виконані.
  `toggleDoneToday()` при позначці виконаним сам прибирає звичку з черги.
- **Звичка з черги з барабана виходить** (`getWheelCandidates` відсіює `wheelQueue`).
  Сценарій користувача: набрати спінами, скажімо, 10 різних справ, а потім виконувати —
  тож жодна не має випадати вдруге. Повертається, коли її виконано або прибрано з
  черги (✕ / «Очистити»). Це стосується і пріоритету за частотою: «пора» звички, що
  вже в черзі, не займають пул, тому лічильник «⏰ N пріоритетних» і «N звичок у
  барабані» зменшуються з кожним спіном. Коли всі доступні вже в черзі — порожній
  стан із відповідним повідомленням і неактивною кнопкою (`isWheelEligible` відрізняє
  «усе в черзі» від «звичок у барабані немає»).
- Переможця для блоку в барабані (`picked` у `renderReelIdle`) шукати серед **усіх**
  звичок, а не серед кандидатів: щойно обрана вже в черзі й кандидатом не є.
- Стан кнопки «Крутити» виставляє лише `renderReelIdle()`. Не вмикати її вручну після
  `showWheelResult()`: `render()` усередині вже її порахував, і ручне ввімкнення
  перетирало «вимкнено», коли барабан порожній.

### Пріоритет у барабані (`pickWinnerIndex`)

> Бекенд зберігає `everyDays` (колонка в `backend/Code.gs`); зворотний прохід на живій
> Таблиці пройдено 2026-10-18 — значення зберігається й повертається, оригінал
> відновлено ідентично.

Рівноймовірного вибору більше немає — `spin()` кличе `pickWinnerIndex(candidates)`.
Переможець, як і раніше, обирається **індексом наперед**, тож анімація не змінилась.

1. **Частота.** `everyDaysOf(h)` — ціле 1..365 або `null`. `dueInfo(h)` повертає
   `{ late }`, коли звичка «пора»: з останнього виконання минуло ≥ N днів, або вона
   ще жодного разу не виконувалась (тоді `late` = днів від створення мінус N).
   Поки в барабані є хоч одна «пора» — випадає лише одна з них (гарантія).
   Виконана сьогодні звичка «пора» бути не може (0 < N).
2. **Вага за занедбаність** — всередині пулу (або всього барабана, якщо «пора» немає).
   `neglectWeight` = `1 + min(днів без виконання, NEGLECT_CAP_DAYS) / NEGLECT_STEP_DAYS`,
   тобто +1 за кожні 2 дні, максимум 8× (при 14+ днях). Для ніколи не виконаних —
   відлік від `createdAt`. Константи — на початку IIFE.

Перевірено на тестовій копії з підмінним `fetch` (400 і 1000 спінів): із двох
«пора» випадали лише вони, у пропорції ваг 2:8; без «пора» розподіл збігся з
теорією ±2 п.п.

UI частоти — **вибір одним дотиком, без режиму редагування**. У кожного рядка завжди
є чип «🔁 частота» (порожній, пунктирний) або «🔁 щодня / раз на N дн.»; дотик по ньому
відкриває під рядком `buildFreqPicker`: «щодня», «раз на 3 дні», «раз на тиждень»,
«раз на 2 тижні», «раз на місяць» (`FREQ_PRESETS`) — один дотик зберігає й закриває —
плюс «інше…» (поле з `inputmode="numeric"` і явна кнопка «Зберегти») та «без частоти».
Поле не лежить у режимі редагування назви навмисно: після олівця фокус іде в назву з
виділеним текстом, а на телефоні це давало 5+ дотиків на одну звичку.

- Цифрова клавіатура iOS не має кнопки «Готово/Return», тому для довільного числа
  потрібна явна кнопка «Зберегти» поруч із полем. Число поза 1..365 не зберігається
  (поле підсвічується).
- Відкритий вибір один на всю сторінку (`freqPickerId`): відкриття іншого закриває
  попередній, повторний дотик по чипу — закриває. Скидається при олівці, смітнику й
  вході в режим вибору кількох.
- Чип «⏰ пора» — без числа прострочених днів: «пора» рахується від останнього
  виконання, а не від дня, коли вказали частоту, тож «прострочено» вводило б в оману.
  Над барабаном лічильник «⏰ N пріоритетних», у результаті спіна — причина.

### Статистика

- `currentStreak` — рахує серію від сьогодні назад; якщо сьогодні ще не
  виконано, стартує з учора (щоб серія не «ламалась» до кінця дня).
- `last7` в overview — сума **усіх** виконань усіх звичок за 7 днів, а не
  кількість днів.
- `pluralUk()` — українські закінчення (звичка/звички/звичок). Використовувати
  для будь-яких нових числівників.

  тексту). Вимагає інтернету.
- Іконки — інлайн SVG через `ICONS` + `icon(name, size)`.
- Версія в футері прописана руками (`build v5`) — оновлювати при значних змінах.

## Деплой

Гілка `main` — це **продакшн**: GitHub Pages роздає корінь репозиторію на
<https://kazmirchuk96.github.io/habit-tracker/>, і трекер відкривають з телефона.
Конфігу Pages у файлах немає — він живе тільки в налаштуваннях GitHub
(`gh api repos/kazmirchuk96/habit-tracker/pages`).

Отже: **закомітив → одразу запушив**, інакше зміни не існує для користувача.
Збірка Pages займає ~30 с; перед тим як казати «готово», дочекатись статусу
`built` і звірити живу сторінку з локальним файлом.

Версія у футері (`build vN`) — найшвидший спосіб зрозуміти, яку версію
завантажив браузер. Якщо після деплою телефон показує стару — це кеш браузера.
